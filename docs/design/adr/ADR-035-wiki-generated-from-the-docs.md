# ADR-035 The GitHub wiki is generated from the user documentation

- **Context:** the owner asked for a GitHub wiki for the project (2026-11-14). The user documentation already exists: `README.md` and `docs/*.md`, written from the design docs, reviewed in pull requests, checked by the `docs-links` workflow and shipped in the release zip (ADR-029). A wiki maintained by hand would be a second copy that drifts from it. Wiki edits are not reviewed, and for a tool used with real money a wrong lot-size explanation or a changed download link is a safety problem. GitHub wikis are separate git repositories (`<repo>.wiki.git`): a push can replace them, but GitHub creates that repository only when the first page is saved in the browser.
- **Decision:**
  - **The repository stays the only source.** The wiki is a generated copy of `README.md` (the Home page), every `docs/*.md` and `ROADMAP.md`. The design docs, the ADRs, `CHANGELOG.md`, `CONTRIBUTING.md` and the other repository files are not copied; wiki pages link to them on GitHub.
  - **`build/publish-wiki.ps1`** writes the pages: it drops each file's leading `# ` heading (the wiki shows the page name as the title), rewrites relative links (to a page: its wiki URL, anchor kept; to any other file or folder: its `blob`/`tree` URL on `main`), adds a last line naming the source file, and writes `_Sidebar.md` and `_Footer.md`. It stops when a link points at a missing file or a `docs/*.md` has no page in its page list. With `-Publish` it replaces all the wiki's pages, removing pages that no longer have a source, and pushes; nothing is pushed when nothing changed. Locally it refuses while a source file has uncommitted changes.
  - **`.github/workflows/wiki.yml`** runs `publish-wiki.ps1 -Publish` on every push to `main` that changes a source file, the script or the workflow, and on demand. It pushes with `GITHUB_TOKEN` (`contents: write`), passed to git as an HTTP header through the environment, never on a command line. Pull requests publish nothing; `test-build-scripts.ps1` (the `scripts` workflow, which now also runs on changes to `README.md` and `ROADMAP.md`) checks that every page is written with no relative link left.
- **Consequences:**
  - A documentation change reaches the wiki when it is merged to `main`, never before. The wiki's history is a list of `github-actions[bot]` commits named after the source commit.
  - The wiki is never edited by hand. Each page and the footer say so and link to the source file; a hand edit is overwritten by the next run.
  - A new file in `docs/` needs a row in the script's page list. Without it the `scripts` workflow fails on the pull request.
  - Once per repository the first wiki page has to be created in the browser; until then `-Publish` fails with that instruction.
  - Who may edit the wiki is a repository setting (*Restrict editing to collaborators only*), outside this decision. It is recommended, because a public wiki can otherwise be edited by any GitHub user until the next run.
  - **Verified 2026-11-14:** locally, Windows PowerShell 5.1 and PowerShell 7 wrote the same 12 files from the documentation; apart from the dropped heading and the added source line each page equals its source except for link targets; a missing link target, a `docs/*.md` without a page and a non-empty `-OutDir` each stop the script; `-Publish` before the first page exists stops with the instruction, and the token variables and the temporary clone are removed afterwards. `test-build-scripts.ps1` passed 13 of 13 checks with both shells. After the owner created the first page, `-Publish` run locally replaced it with the 12 files (wiki commit `cca059b`), and a second run found nothing to change. On GitHub the pages show the sidebar and footer, the risk disclaimer as an alert box, and links between pages with their anchors (`Configuration#take-profit`). Not yet verified: the push with `GITHUB_TOKEN` from the workflow, which first runs after this is merged to `main`.
