# ADR-031 1.8.0 is released as the first stable version before the P8 hardening

- **Context:** ADR-029 planned 1.8.0 as the first stable release *after* P8: tests that force the untested safety paths (T-29 close-if-SL-fails, T-35 ambiguous result without blind resend, the MT5 filling-policy fallback after a real rejection), the full demo test matrix (T-01 to T-31) and a review of the trade gateway against design/03 §6. On 2026-11-13, with none of that done, the owner decided to release the stable version now. Since 1.7.0 only the build tooling changed (CI releases, ADR-030; `build/check-version.ps1`); the trading code is identical.
- **Decision:** Publish 1.8.0 as a normal (non-pre-release) GitHub release through the CI workflow of ADR-030. The P8 work stays planned, now for the next minor version (`ROADMAP.md`, "Hardening"). The documentation keeps stating the limits plainly: tested on demo accounts only, not on live accounts, three safety paths not yet triggered on a real server (README "Known limitations", `docs/broker-compatibility.md`).
- **Consequences:** "Stable" here means a supported release line with SemVer guarantees (SECURITY.md supports 1.8.x, no longer 1.7.x), not that the P8 checks passed. The release notes and the README say so. This supersedes the part of ADR-029 that tied the first stable release to P8; the rest of ADR-029 stands. Evidence for the 1.8.0 build: build 8 of 8 with 0 errors and 0 warnings locally and in CI, unit tests (RiskDeskTests) on MT4 and MT5; the panel, trade and broker reports are from the internal 0.4.0 to 0.7.0 builds, whose trading code is the same.
