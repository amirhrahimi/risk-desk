# ADR-030 Releases are built and published by CI

- **Context:** The owner wants MT4 and MT5 builds published for every push and pull request to `main` (2026-11-13), following standard practice. Until then a release meant running `build/package-release.ps1` on the owner's PC and uploading the zip by hand, and CI compiled MT5 only, because MetaQuotes was thought to offer no public MT4 installer. A test on a GitHub-hosted Windows runner showed that `mt4setup.exe` from MetaQuotes' download server installs MetaTrader 4 with `metaeditor.exe` (build 5.0.0.2425, the same as the owner's), and all eight targets compiled with 0 errors and 0 warnings.
- **Decision:**
  - `.github/workflows/build.yml` replaces the MT5-only compile check. On every pull request to `main` and every push to `main` it installs MetaTrader 4 and 5 from MetaQuotes' installers, compiles the eight targets (fails on any error or warning, rule R11), packs them with `build/package-release.ps1 -SkipBuild` and attaches the package to the workflow run.
  - **Pull requests never create a release:** their code is not merged yet, and on a public repository a pull request from a fork gets a read-only token.
  - **Push to `main`, version without a release:** when `RD_VERSION` in `Build.mqh` has no release yet, the workflow creates `v<RD_VERSION>` at that commit, with the zip, its `.sha256.txt` and the `## [x.y.z]` section of `CHANGELOG.md` as notes. It fails instead when that section is missing or when the tag already exists at another commit. Following SemVer, only a version with a pre-release part (`1.8.0-rc.1`) is published as a GitHub pre-release; `RD_VERSION_PROP` keeps the plain `x.yz` form. 1.7.0 was marked as a pre-release by hand once, because it was named before this rule (ADR-029).
  - **Any other push to `main`:** the workflow replaces a single pre-release *Development build* (tag `dev`, asset `RiskDesk-dev-<commit>.zip`) with a build of that commit, so the latest `main` is always downloadable. Its notes say it is untested and list the `[Unreleased]` changes.
  - **Version check:** the version stays in `Build.mqh` (MetaEditor has no command-line define, and a build made directly in MetaEditor must still report its version). `build/check-version.ps1`, run by `build.ps1` and as the first CI step, fails when `RD_VERSION` is not SemVer, when minor or patch is above 9, or when `RD_VERSION_PROP` is not its `x.yz` form (ADR-029).
  - **Build metadata:** a build that is not a release gets its commit appended to `RD_VERSION` on the runner before compiling (SemVer build metadata): `1.7.0+dev.abc1234` on `main`, `1.7.0+pr.12.abc1234` for pull request 12. The change is never committed; released builds report the plain version.
- **Consequences:** Releasing is a version bump plus a CHANGELOG section, merged to `main`; nothing is uploaded by hand. The log's start line, the panel's ready message and the BrokerProbe/GatewaySmoke reports of a development build name its commit, so a bug report identifies the exact build. CI depends on MetaQuotes' download server and installers: if `mt4setup.exe` stops installing MetaTrader 4, the build fails and `build/build.ps1` plus `package-release.ps1` on a local machine remain the fallback. The tag `dev` moves with every push, so a local `git fetch --tags` may report that it would clobber an existing `dev` tag.
- **Superseded in part:** since ADR-033 the `build` job runs on `ubuntu-latest`, with MetaEditor under Wine; everything else here stands.
