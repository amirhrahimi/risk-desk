# ADR-031 Fault injection for the safety paths, and BC-14 ignores older trades

- **Context:** Three safety paths had never run against a real server, because a healthy demo server never takes them: closing a position whose SL cannot be attached (rule R7, T-29), the ambiguous result without a blind resend (rule R9, BC-14, T-35) and the MT5 filling-policy fallback after a real rejection (BC-06). `08-testing.md` described hidden inputs (`InpTestFailSlAttach`, `InpTestForceAmbiguous`, `InpTestForceFill`) for them, but the code had none: only `InpTestUiSelfTest` existed. Writing the tests also showed a defect in BC-14: the check for "did the lost request execute?" accepted any trade with the same symbol, magic, side and volume opened within 5 s before the request, so a trade from the seconds before (a second click, the previous test case) was taken for the lost request. The panel then said "done" and named the old ticket although nothing had been opened, or on MT5 reported "executed but the position was not found".
- **Decision:**
  - **Faults are armed by the self-test, not by inputs.** `CTradeGatewayBase` has, under `RD_TEST_HOOKS` only, an armed fault (`EGwFault`): `GWFAULT_SL_ATTACH` (the open goes out without SL/TP and every SL/TP modify is refused, so the verify step must close the position or warn), `GWFAULT_REPLY_LOST` (the first open is sent and executes, its reply is dropped), `GWFAULT_SEND_LOST` (the first open is not sent), `GWFAULT_NEVER_ANSWERED` (no open is sent) and `GWFAULT_BAD_FILL` (MT5: the first filling policy of the ladder is one the symbol's flags do not allow, so the server really answers 10030). A fault changes what is sent or what the terminal is told, never what the gateway does with the answer, so the code under test is the production code. Only market opens are affected; closes, modifies and deletes are not. A release build contains none of it.
  - **The `safety` suite** (`build/run-uitest.ps1 -Suite safety`, `App/UiSelfTestSafety.mqh`) arms a fault, clicks the real Buy button on a demo account (rule R13, own magic, minimum-risk lots) and checks the position count, the status bar and the lines the gateway wrote to the daily log file (read from where the file ended before the click). It replaces the hidden inputs of 08-testing section 2.
  - **BC-14 ignores what existed before the request.** At the first send the gateway records the deals, positions and orders of ours (same symbol and magic) that already exist (`Baseline`, at most 16 tickets); the ambiguity check skips them, so only something that appeared after the request can be its effect. The 5 s window stays, for server/terminal clock differences. BC-14 in `03-broker-compatibility.md` is amended accordingly.
- **Consequences:** T-29, T-35 and the filling fallback can be run unattended on every demo account and are a regression test for the three rules. The fault code is one more thing to keep compiling in debug builds. The suite needs a market that is open: on a weekend only the symbols that trade then (crypto CFDs) can be used. A fault test does not prove how a particular broker's server behaves when it really times out; it proves what Risk Desk does with such an answer.
