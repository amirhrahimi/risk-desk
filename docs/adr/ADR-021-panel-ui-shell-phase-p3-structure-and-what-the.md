# ADR-021 Panel UI shell (phase P3): structure, and what the first runs on the owner's terminals changed

- **Context:** 05, 07 and 02 describe the panel; building it and running it on two real terminals (MT5 A3, MT4 A1, both at 120 DPI = 125 %) left points open and showed three places where the spec did not hold: the clamp of 05 §3 let an auto-fitted panel hang off the bottom of the chart (T-37 requires "always fully visible"); with fonts floored at 6 pt (05 §1) but rows still shrinking, small scales overlapped the status lines and clipped "Risk %"; and MT4 drew the ✥ handle glyph as "?". The P3 tests (T-01, T-02, T-20, T-21, T-37) also needed a way to run without a person clicking.
- **Decision:**
  - Files outside the CLAUDE.md §4 layout, split like ADR-019 (class declared in one file, some method bodies in a companion included at its end): `UI/PanelObjects.mqh` (CPanel's object names, types, captions), `App/ControllerModel.mqh` (view model, idle readout), `App/UiSelfTest.mqh` + `App/UiSelfTestSteps.mqh` (debug builds only), `build/run-uitest.ps1`.
  - Structure: `CSettings` is a plain record with public fields, filled and validated once by `Load()`; modules hold pointers to it. The Controller builds an `SPanelModel` every refresh, `CPanel` renders it, every widget writes only properties that changed, and one shared `CRdRedraw` issues at most one `ChartRedraw()` per cycle. `EPanelButton` lives in `UI/Theme.mqh` (UI, State and Controller share it). The trading buttons answer amber "<Button>: not implemented yet (coming in phase Pn)" (09 P3).
  - Input bounds where 07 gives none (clamped with a warning in the log and the first status message): risk caps 0.01–100 %, default risk 0.01–cap, commission ≥ 0, margin buffer 0–90 %, magic ≥ 1 (0 would make manual trades "tool trades"), comment ≤ 31 characters, slippage 0–100000, retries 0–10, retry delay 0–10000 ms, expiry 0–8760 h, cooldown 0–10000 ms, Risk Free extra 0–100000 pts, font sizes of candle time / SL label 6–36, candle warn 0–86400 s, screenshot size 0–8000, X/Y Start 0–20000, spread warning ≥ 0, status hold 1–600 s, line width 1–5, cent divisor 1–10⁶, stale quote 0–604800 s.
  - **Clamp (05 §3 changed):** the whole panel stays in view, `y ≤ chartHeight − shown panel height` (handle to camera, or to the title row when hidden), instead of `chartHeight − 40`. The saved position stays the user's; the shown one is clamped, so the panel returns when the window grows. A panel taller than the chart (scale already 0.40) keeps its top-left corner in view.
  - **Font-aware rows (05 §1 refined):** every row is at least one text line tall in its font (`TextGetSize`), the caption column at least as wide as "Risk %"; a row that grows moves the rows below it. Button and field texts that are still too wide get a smaller font (down to 6 pt). Auto-fit (F-34) searches the 0.01 grid on the real pixel height and takes the largest step that fits. At scale 0.40 and 125 % DPI the panel is 342 px tall (276 px if it scaled linearly).
  - **MT4 glyphs:** MT4 draws chart-object text in the ANSI code page (characters outside Windows-1252 become "?"; —, –, …, € survive). `Platform/Compat.mqh` has `RD_OBJ_TEXT_UNICODE`; MT5 uses Segoe UI Symbol ✥ (U+2725) and 📷 (U+1F4F7), MT4 uses Wingdings 0x76 (❖) for the handle and Webdings 0xB5 (camera), picked from glyph sheets drawn on MT4 itself (codes 0x80–0x9F do not survive the mapping).
  - Objects: the move handle is a small `OBJ_BUTTON` (05 allows it; it has its own background, so it is visible on any chart colour); the title is two labels, `RD_P_TITLE` "Risk" and `RD_P_TITLE2` "Desk" in the accent colour; captions `RD_L_RISK`, `RD_L_LOTS`, `RD_L_PINFO`. Drawing order is creation order, so when only some panel objects exist all are deleted and created again; a panel object deleted by the user is rebuilt within a second.
  - **Symbol change (02 §8 changed):** a hidden chart object `RD_S_CHART` holds the chart's symbol, instead of `chart_<ChartID>.ini`. Chart IDs are not stable across sessions, so a stale file of another chart could delete lines that a restarted terminal restores from its profile; the object lives and dies with the chart. A different symbol at `OnInit` deletes `RD_LN_*` / `RD_LT_*` with the amber note "Lines removed: the chart changed from EURUSD to GBPUSD".
  - An EA keeps its objects across a timeframe or symbol change (the terminal calls `OnDeinit`/`OnInit` without reloading it): `CState.loaded` keeps the panel state in memory, `ui.ini` is read once per program run and written only when this chart changed something (several charts share it, D17). The controller measures the chart again on every `OnInit`.
  - Idle readout priority: BC-15 terminal/account permissions, the symbol's trade mode, missing or stale quote (BC-17), MT4 tick-value mismatch on the chart symbol (BC-05, checked with every 60 s spec read), then "Open risk x % / cap" (F-29) from fresh lists of RiskDesk positions and orders on the whole account every 2 s (gateway `List*`, read-only).
  - BC-15 trade modes (D19): a symbol whose trade mode forbids a button draws it grey with the reason as tooltip; a click answers red with the same reason.
  - **Chart look** (found by the owner on a saved MT4 chart after the first P3 build; the self-test's fresh charts had neither setting): "Chart on foreground" draws the price chart above every object, so candles covered the buttons (and would cover P4's SL/TP lines). RiskDesk switches it off while it runs (checked on init, on every chart change and every second, D20) and gives the user's value back when it leaves the chart; that value is kept in `RD_S_CHART`, so a terminal restart does not lose it. The One-Click Trading panel is a terminal overlay in the chart's top-left corner, drawn above every object; it hid the title, Risk % and the move handle, so the panel could not even be dragged away. Measured on window captures of MT4 build 1492 and MT5 build 6311: 203 × 79 px at 96 DPI on both. While it is shown, the clamp keeps the panel out of a 215 × 90 px corner (× DPI / 96): below it when the panel fits there, else to its right.
  - **Debug self-test** (`RD_TEST_HOOKS`, input `InpTestUiSelfTest`, `build/run-uitest.ps1`): attaches RiskDesk to a temporary chart, drives the handlers a user triggers (`OBJECT_ENDEDIT`, `OBJECT_CLICK`, `MOUSE_MOVE`, `ChartSetSymbolPeriod`), checks the results, saves chart screenshots and a PASS/FAIL report in `Files/RiskDesk/uitest/`, then removes itself and closes the terminal (no chart is closed). It runs only when the runner left the one-time file `Files/RiskDesk/uitest.request`, so a chart kept in a profile never re-runs it, and it reads and writes `ui.ini` / `acct_<login>.ini` only in the sandbox `Files/RiskDesk/uitest/store/`: the owner's saved state is never touched. T-21 is checked across two runs: the first saves Risk % 0.75, a moved and hidden panel and writes what it expects; the second, after the real terminal restart, compares. `ChartScreenShot` renders the chart with its price and time scales into the size asked for, so the self-test asks for the chart size + 100 × 40 px; it does not draw terminal overlays such as One-Click Trading, so for those the self-test writes `uitest/capture.request` and the runner captures the real terminal window (`PrintWindow`). The self-test switches One-Click Trading off for its main checks and on for the chart-look checks, and restores the chart's value at the end.
- **Consequences:** T-01, T-02, T-20 (panel part), T-21 and T-37 run unattended on both platforms (60 checks, 0 failures on A1 and A3); RiskDesk changes one chart setting while it runs (Chart on foreground); T-24 (Windows scaling 150 % / 200 %) and real mouse/keyboard input stay with the owner. 05 §1/§3, 02 §8/§11 and 08 §3d updated. The panel is taller than 05's diagram suggests at small scales, by design.
